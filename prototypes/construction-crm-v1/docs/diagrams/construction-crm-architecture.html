Selected with the owner

Both Build and Operate modes. Hybrid delivery: hosted lead intake, private dashboard and local coding runner. Warm paper, dark ink and construction orange.

Proposed to control usage

2D pixel sprites, a deterministic scheduler and event replay. No model calls for movement, game loops, scoring, retries or dashboard narration.

01 / LOGICAL ARCHITECTURE

One yard. Two kinds of work.

A public business journey and a private engineering tool share a visual language. They keep their execution, credentials and data authorities separate.

The dashboard initiates outbound authenticated HTTPS. No inbound cloud command or public tunnel reaches the coding runner. Full contracts and failure paths are in the design document.

02 / BUILD MODE

Skills equip workers. Evidence builds the project.

The engineer commissions changes to the CRM. Only actual reasoning or coding starts a model session; dispatch, tests and rendering are ordinary code.

A skill is an instruction package, not another model. A builder can carry several skills. Default to one active model task; retain the existing two-run ceiling. Scene animation does not call a model.

03 / OPERATE MODE

From enquiry to a verified consultation.

Booking stays available while qualification or CRM sync is delayed. Hosted services preserve work; the private scene shows verified state and exceptions.

Browser redirects and widget messages are hints. Confirm bookings server-side from supported provider evidence; reconcile if necessary. Meeting creation, cancellation and rescheduling require a credentialed integration spike. A HOT lead is not automatically an appointment.

04 / HYBRID DEPLOYMENT

Public intake keeps working while the laptop sleeps.

V1 deploys one business instance. Public source, a browser interface and an optional future desktop launcher describe different parts of the same product.

V1 chip tags identify planned authored artifacts, not shipped releases. Pin third-party engine and API versions during baseline recovery and the integration spike. Internal workers/database have no public listener. The public demo remains synthetic and credential-free.

05 / LOGICAL DATA MODEL

Keep business truth and build history durable.

Each installation owns two stores. Shared identifiers correlate work; the browser projects a sanitized view rather than becoming the source of truth.

Cardinality is conceptual. Task/actor assignment and provider linkage need explicit validation; there are no cross-database foreign keys. Appointments can remain unmatched until reviewed. Additional audit, connection and policy tables are specified in the design document.

06 / USER EXPERIENCE

Install once. Build deliberately. Operate continuously.

  1. Try a public synthetic demo, with no accounts or model calls.
  2. Download a GitHub release and start the private local browser app.
  3. Connect a project folder, coding runtime, selected skills and a usage budget.
  4. Deploy the business intake service and connect a HubSpot test account and scheduling link.
  5. Commission a change in Build mode. Inspect outputs and accept a concrete release.
  6. Switch to Operate mode to see intake, CRM sync, verified consultations and exceptions.
  7. Close the laptop: hosted lead intake continues. Reopen the app to replay missed events.
